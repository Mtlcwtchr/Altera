# Ядро террейна, этап 1: высоты и стриминг. Замеры

Ветка `rework/terrain-core`. Машина: RTX 3070 Laptop (8 ГБ), Vulkan, 1920×1080, headless.
Каждый кадр ждёт GPU (`--sync`), поэтому «кадр» = CPU + GPU, без перекрытия.
Движение скриптовое, шаг 1/60 с: столько камера проходит за кадр при 60 fps.

Воспроизвести:

```
cmake --build cmake-build-windows --target terrain_lab campfire_terrain_core_tests
python tools/terrain_lab/sweep.py --out doc/reports/terrain_core/step1
cmake-build-windows/terrain_lab.exe --world-km 2000 --spacing 0.5 --view-km 32   # полетать: WASD, ПКМ, колесо, F1
```

## Что построено

- `src/terrain_core/` — ядро. Знает только `engine::Device`, ни строчки из игры.
  - `MacroMap` — 16-битная макрокарта на весь мир (импорт PNG16 или генератор,
    который пишет такой же PNG16), min/max-пирамида для отсечения.
  - `Clipmap` — L уровней по N×N текселей, тороидальная адресация. Отдаёт ровно
    те полосы, что вошли в окно (тест это проверяет).
  - `select()` — CDLOD: квадродерево по миру, морф к сетке родителя, четверти
    узлов. Тесты: земля покрыта патчами ровно один раз, у глаза — уровень 0.
  - `Renderer` — compute-генерация полос, один instanced-draw на четверть узла
    (4 draw call на весь террейн), никакого меша на CPU.
- `assets/shaders/terrain_core/` — `height.hlsli` (макро бикубик + октавы
  градиентного шума с аналитическими производными), `generate.hlsl`,
  `terrain.hlsl` (VS поднимает сетку и морфит, FS — солнце, небо, туман).
- `tools/terrain_lab/` — приложение-стенд и `sweep.py` для матрицы замеров.

Генерация идёт **в том же командном буфере, что и отрисовка**, до неё. Всё, что
вошло в кадр, сгенерировано в этом же кадре — отставать стримингу некуда.

## Как параметры влияют на результат

**Шаг s (0.25 / 0.5 / 1 / 2 м)** на стоимость кадра почти не влияет (±0.05 мс):
число патчей определяет сетка G, а не шаг. Мелкий шаг добавляет 1–2 уровня ради
той же дальности (+1 МБ и +~0.02 мс за уровень) и больше текселей на кадр при
быстром движении (65 тыс. при 0.5 м против 117 тыс. при 0.25 м на 3000 м/с), что
всё равно копейки. **Шаг выбирается из того, что должно быть видно под ногами, а
не из бюджета.**

**Сетка G задаёт плотность треугольников на экране.** На границе LOD длина ребра
≈ `H / fov / (rangeFactor·G)` пикселей: при 1080p и rangeFactor 2.5 это 26 px
для G=16, **13 px для G=32** и 6.4 px для G=64. Стоимость: 86 тыс. / 300 тыс. /
1 млн треугольников, т.е. 0.4 / 0.45 / 0.6 мс кадр в полёте.

**Клипмап N** определяется сеткой: окно должно вмещать узел самого дальнего
диапазона уровня, `N/2 ≥ (rangeFactor + √2)·G + 2`. Отсюда пары 128/16, 256/32,
512/64 — все прошли без промахов покрытия. Память: RGBA32F, 16 Б на тексель, т.е.
1 МБ на уровень при N=256 и 4 МБ при N=512.

**Дальность видимости почти бесплатна:** каждое удвоение — +1 уровень. 8 → 64 км
стоит +50 тыс. треугольников и ~0.1 мс.

**Размер мира не влияет вообще** (16 / 256 / 2000 км — одинаково): всё зависит
только от окрестности камеры.

| пресет | шаг | N | G | уровней (≈41 км) | клипмап | треуг. | кадр (полёт) |
|---|---|---|---|---|---|---|---|
| **базовый** | 0.5 м | 256 | 32 | 11 | 11 МБ | 300 тыс. | 0.44 мс |
| качество | 0.5 м | 512 | 64 | 10 | 40 МБ | 1 млн | 0.6 мс |

Террейн занимает ~3% кадра в 16.6 мс — запас под материалы (этап 2) и фолиаж (этап 3) огромный.

## Ограничения и что не проверено

- **Выбросы кадра до ~2.5 мс** (по 1–2 на сценарий) — разовый прогрев пулов
  SDL/драйвера по счётчику кадров. Выброс всегда на одном и том же кадре и
  пропадает, если запустить сценарий отдельно; генерация в эти кадры не идёт.
  Один настоящий выброс — отдельный submit загрузки патчей каждый кадр — найден и
  убран: загрузка теперь идёт в командном буфере кадра.
- «Бесшовность» морфа проверена на стоп-кадрах (уровни подкрашены: `lod_rings.png`,
  швов нет) и по отсутствию промахов, а не численной метрикой «попа». Нужен живой
  облёт: `terrain_lab` в окне, F1 переключает отладочные виды.
- Высоту под камерой CPU узнаёт через readback из клипмапа с задержкой 2 кадра.
  Для геймплея (коллизии, ИИ) понадобится CPU-версия той же функции высоты —
  отдельная задача.
- За дальностью видимости ничего нет. При наборе высоты до 20 км горизонт
  обрывается на 41 км — нужен дальний слой только из макрокарты (дёшево).
- Генератор макрокарты — заглушка для замеров, не арт.
- Клипмап хранится в RGBA32F; R32F высота + RG16F градиент вдвое сократят память.
  Сейчас не нужно.
