# Крафт: данные и язык craft-expr (K1/K2)

Реализация дизайна `gdd/crafting/CRAFTING_DESIGN.md` v0.2. Данные: `content/ai/craft/*.json`, тексты: `content/loc/{ru,en}/craft.json`. Код: `src/sim/craft/` (`craft_expr` язык, `craft_data` загрузка, `craft` резолвер шага, `craft_chain` цепочки/книга рецептов/fast craft, `craft_validate` валидатор). Отчёт по исходам: `altera_craft_report`.

## 1. Язык craft-expr

```
expr    := or ( '?' expr ':' expr )?
or      := and ( ('or' | '||') and )*
and     := not ( ('and' | '&&') not )*
not     := ('not' | '!') not | cmp
cmp     := add ( ('<' | '<=' | '>' | '>=' | '==' | '!=') add )?
add     := mul ( ('+' | '-') mul )*
mul     := unary ( ('*' | '/') unary )*
unary   := '-' unary | primary
primary := number | name | name '(' args ')' | '(' expr ')'
name    := [a-z_][a-z0-9_]* ( '.' [a-z0-9_]+ )*
```

Истина = «не 0», сравнения и логика дают 1/0, деление на 0 даёт 0. Числовые функции: `min`, `max` (любое число аргументов), `clamp(x, lo, hi)`, `abs`, `floor`, `ceil`, `round`. Символьные функции берут голое имя: `has(role)`, `count(role)` (детали сборки этой роли), `role(r)` (одиночный кусок сам этой роли), `mass(role)` / `mass()`, `flaw(id)`, `state(id)`, `tag(t)`, `eff(effect)`.

### Имена

| имя | что |
|---|---|
| свойство (`hardness`, `edge`, ...) | свойство вещи; у сборки смешано по деталям правилами `blend` |
| `<роль>.<свойство>`, `<роль>.len/thick/q/mass` | деталь этой роли: `blade`, `head`, `handle`, `shaft`, `stave`, `string`, `binder`, `body` |
| функция (`edge`, `grip`, `food`, ...) | значение функции из `functions.json` (функции считаются по порядку) |
| `shape.<v>` | число формы из `shapes.json` (`cover`, `capacity`, `grip`) |
| `mat.<свойство>` | свойство исходного материала главной детали (до обработки) |
| `q`, `len`, `thick`, `joint`, `solo`, `liquid`, `wear`, `mass` | качество, размеры, прочность соединения, 1 = одиночный кусок, 1 = жидкость, износ, масса |
| в процессах: `x`, `heat`, `even`, `hygiene`, `q` | старое значение, ступень жара, ровность нагрева, чистота станции, качество шага |

Неизвестное имя валидатор считает ошибкой (по таблице выше, ролям из `shapes.json`, изъянам, состояниям, тегам и эффектам).

### Ограничения

Короткая строка условия на число: `>=0.5`, `<0.3`, `2..3` (включительно), `1` (ровно), `==1`, `!=0`. Близость вне условия падает линейно до 0 за `form_match.falloff` (0.25).

## 2. Распознавание архетипа

`forms.json`: жёсткие условия `shape` (у вещи или любой её детали), `mat` (id или тег главного материала), `state`, `profile` (каждый пункт `a|b`: один из тегов есть в профиле), `effects`; остальные ключи `needs` — выражения с ограничением. Оценка = произведение близостей числовых условий; побеждает лучшая с оценкой ≥ `tau` (0.6), при равенстве архетип с большим числом условий, затем более ранний в файле. Ниже `tau` — самоделка `improvised_*` по сильнейшей функции (≥ `improvised_min`) или `improvised_thing`, но только для законченной вещи (сборка, форма стадии `finished`, еда/жидкость после обработки). Иначе вещь промежуточная: имя «материал + форма».

## 3. Шаг (§4.4)

1. `checkStep`: слоты (форма И теги; `either` — форма ИЛИ тег; `p` — ограничения на свойства с учётом временных состояний вроде «раскалённый»), инструмент (теги, `tool_hardness_ge`), станция (теги, `needs` станции), жар (`heat_min`), режим, целевая форма из `shape_map`. Отказ = код `craft.reason.<code>`.
2. Сложность `d = base + add(work)`. Компетентность `c = навык + 0.15·q_инстр + бонус станции + 0.15·знание материала + 0.05·настроение + 0.1·повтор`. Запас `m = c − d`.
3. Исход по `z = m + noise·(u1 + u2 − 1)`: катастрофа (только `risky`) / испорчено (< `flawed`) / с изъяном (< `ok`) / нормально / хорошо / образцово.
4. Качество шага `q = 0.5 + 0.45·tanh(2k·m) + шум` (мягкое насыщение: у мастера вещи всё равно немного разные), черты добавляют `quality`.
5. Операция (`op`): `shape`, `heat` (реакции материала на жар, кокс/уголь как со-вход), `blend` (смешение по `blend`, эффекты концентрацией по массе, реакции), `join` (сборка, роли деталей по форме, прочность соединения от качества и связки), `soak`. Затем `transform`, `set_state`, `to_material`, реакции, `refine` материала, состояния.
6. Изъяны по правилам процесса (`p`, `when`), при исходе «с изъяном» минимум один; `fixes` снимает изъяны при `q ≥ 0.5`.
7. Испорчено: остатки 30–60% массы (материал из `salvage` изъяна/материала или сам материал).
8. Опыт навыка: `rate·(1 − навык)`, полный в окне `|m| ≤ 0.25`, иначе 0.3; провал ×0.4. Знание материала растёт.

Качество вещи = 0.7·среднее шагов (сырьё считается как шаг) + 0.3·слабейший шаг.

## 4. Цепочки, книга рецептов, fast craft (§16–§17)

История вещи (`trace`) — шаги с входами `mat:<id>` / `form:<id>` / `step:<n>`. `designs.json` — стартовые образцы в том же формате (по одному на архетип). Запись книги рецептов = шаги + `known` по каждому; первая удача раскрывает последний шаг и около трети остальных, каждый следующий успех — ещё один; мастерство ≥ 0.85 и 5 успехов раскрывают всё. `runChain` (fast craft): берёт входы со склада, пропускает стадии, результат которых уже лежит на складе, лимит 12 стадий, останавливается с кодом `craft.stop.<code>` (нет материала, нельзя начать, испорчено, поранился, слишком длинно); сделанное остаётся.

## 5. Отклонения данных K1 от черновика

Формулы черновика были описательными; при формализации данные приведены к языку:
- `transform` стал словарём «свойство → выражение»; особые действия — отдельные поля (`set_state`, `to_material`, `marks`, `fixes`, `reacts`, `extract`).
- Нагрев: `heat` материала — список реакций с `at`, `no_air`, `needs_dry`, `needs`, `modes`, `when`, `to`/`to_state`+`set`/`result`; горение, плавление смолы и вытапливание сала убраны (их результат никому не нужен).
- Новые процессы: `knap` (оббивка кремня), `link` (плетение кольчуги из проволоки), `mill` (помол). У `heat` есть слот `with` (уголь для науглероживания), у `join` — правило `assemble` (клёпки + обруч → бочарная заготовка).
- Новые формы (`shapes.json`) с ролью, стадией и размерами; формы `blade`, `ring_mail`, `cask_raw`, `boot_raw`, `whet_blank` добавлены, потому что архетипы их требовали, а процессы не давали.
- Материалы: стартовая форма и размеры, `item` (что в мире даёт материал), `raw`, `salvage`, `refine` (крица → кованое железо при ковке, ячмень → солод при сушке после замачивания), науглероживание железа в сталь. Новые: `alcohol`, `vinegar`, `lye`, `soap`, `mortar_lime`, `curd`, `shards`, `scrap`. Поправлены: ясень гибче (лук), у ивовой коры и шерсти есть вязкость, у льна теплота.
- Реакции: `maillard_bread` убрана (хлеб распознаётся архетипом по профилю), `when` формализован (теги `a|b`, `no_air`, `no_yeast`, `eff:x`, условия на свойства), `ratio` у бронзы.
- Архетипы: условия переписаны в выражения (`has(handle)`, `blade.len`, `head.edge`), добавлены `bowl`, `cider`, `thread`, `fishing_net`, `roof_tile`; `item` связывает архетип с предметом сима (`axe`, `spear`, `tunic`, `bread`, ...).
- Черты в `crafting_config.traits` взяты из существующих (`fastidious`, `handy`, `slob`, `fickle`, `curious`, `lazy`, `diligent`, `stubborn`).
- Навыки: в `knowledge.json` добавлены `smithing`, `carpentry`, `pottery`, `tanning`; «портняжное дело» = существующий `sewing`.
- Каналы экстракции (`extract` у эффектов) пока не различаются: эффект трав идёт в смесь полностью, процессы только помечают способ. Это упрощение v1.
