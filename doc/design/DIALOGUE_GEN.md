## 0. Коротко

Реплика собирается в **три слоя**, и только последний знает про слова:

1. **Смысл** (сим, без текста): *что* говорится — пропозиция «кто сделал что с кем/чем, где, когда» + речевой акт
   + эпистемика (откуда знаю, насколько уверен, от кого слышал). Слух искажается **здесь**, на смысле, а не на тексте,
   поэтому искажения видит и сим (ложные обвинения, не тот вор), а текст их просто честно проговаривает.
2. **Выбор** (данные, без текста): *как* сказать — какое правило реплики подходит под контекст (акт, тон, отношения,
   характер, уверенность, свежесть, повтор). Механизм — база правил с критериями, побеждает самое конкретное
   подходящее правило (подход Valve «dynamic dialog» / Left 4 Dead), между равными — взвешенный выбор от сида.
3. **Поверхность** (`content/loc/<lang>/`): шаблон с слотами, где слот — не только слово, а **подправило грамматики**
   (рекурсивная раскрытие, как Tracery), плюс морфология языка: падеж, род, число, лицо, вид глагола, одушевлённость,
   предлоги. В коде и данных только ключи и смысловые аргументы.

Ни автомат, ни матрица по отдельности не годятся (§2), но оба остаются на своих местах: **автомат/план** уже ведёт ход
разговора (`dialog_plans`, HTN), **матрица** превращается в критерии правил (тон × отношения × уверенность × черта).

Пример цепочки одного факта (Олег ночью украл у мельника мешок муки; видела Брана):

| Кто говорит | Уверенность | Что в памяти (смысл) | Реплика |
|---|---|---|---|
| Брана, свидетель | 1.0 | theft(Олег, мука×1 мешок, мельник), ночь, амбар | «Сама видела: Олег ночью утащил у мельника мешок муки.» |
| Вера, от Браны | 0.7 | то же, источник Брана | «Брана говорит, Олег стащил у мельника муку.» |
| Ждан, от Веры | 0.49 | предмет → «что-то», время забыто | «Слыхал я, у мельника что-то пропало. Вроде Олег руку приложил.» |
| Лада, от Ждана, болтлива | 0.34 | преувеличение: theft → «обчистил», мешок → «весь амбар» | «Говорят, Олег мельника подчистую обчистил, весь амбар вынес!» |
| Мирон, от Лады, не любит кузнеца | 0.24 → ниже порога | подмена исполнителя: Олег → сын кузнеца | (не пересказывает: ниже `rumorMin`; но в его памяти уже «сын кузнеца») |

## 1. Что не так сейчас

- `dialogue.<template>.<variant>` — плоские строки, слот `{topic}` — существительное. Но тема бывает действием:
  «Это ты {topic}» требует *клаузу* («ты украл хлеб»), «Прости за {topic:acc}» — *именную группу* («за кражу хлеба»),
  «Что знаешь про {topic:acc}» — третью форму. Одна строка-тема на все случаи не склеивается грамматически.
- Нет глаголов как лексем: «взял{who:g||а}» вписывается руками в каждую строку; нет согласования прилагательных,
  одушевлённости (вин. = род. у одушевлённых м.р.), предлогов «о/об/обо», «у + род.».
- Нет эпистемики в тексте: «видел», «говорят», «Брана сказала» — сейчас это отдельные строки `memory.*`, не система.
- Выбор варианта — `pre` + `weight` на шаблоне; нет специфичности, нет памяти о сказанном (повторы), нет голоса
  персонажа.

## 2. Выбор подхода

| Подход | Плюсы | Минусы | Где у нас |
|---|---|---|---|
| Конечный автомат / граф диалога | понятный ход разговора | не порождает текст; комбинаторный взрыв узлов | **ход** диалога (уже есть: `dialog_plans` + HTN) |
| Матрица (тон × отношение × …) → строка | просто | N-мерная таблица растёт как произведение осей, дыры, нет рекурсии | превращаем в **критерии** правил §4 |
| Шаблоны со слотами (как сейчас) | переводчикам привычно | слот = слово, а надо — фраза с согласованием | **основа** поверхности, но слот = подправило |
| Генеративная грамматика (Tracery/CFG с признаками) | рекурсия, разнообразие, слот любого размера | без морфологии ломает падежи | **да**, с признаками рода/падежа/числа из LOC |
| База правил с критериями (Valve/Ruskin) | масштабируется, моддится добавлением правил, «самое конкретное побеждает» | нужен хороший набор фактов контекста | **выбор** реплики |
| Полный NLG-конвейер (SimpleNLG, реализатор по дереву) | идеальная грамматика | тяжело, плохо переводится сообществом, сухой текст | берём идею **фреймов** (роль → падеж) |
| LLM | живой текст | не детерминирован, оффлайн нельзя | только через Agent API (уже решено), берёт наш смысл §3 как вход |

Решение: **смысл (пропозиции) → база правил → грамматика-шаблон с морфологией**. Все три слоя детерминированы от
сида, всё расширяется данными (новый акт / глагол / язык / черта = новые записи JSON, без кода).

## 3. Слой смысла (сим)

### 3.1 Пропозиция

```
Prop {
  pred:  "steal"                       // id предиката из content/ai/predicates.json
  roles: { agent: char#12, theme: item:flour, source: char#4 (жертва), loc: object#77, time: tick }
  qty:   1, unit: "sack"               // необязательно
  neg:   false, modality: "fact|plan|wish|must|can"
  tense: "past|present|future"         // из тика события относительно «сейчас»
}
```

- `predicates.json` (новый, сим): у предиката набор ролей и их типов, *без слов*. Пример:
  `steal: {roles: {agent: char, theme: item|beast, source: char|household}, tags: [theft], from_memory: [saw_crime, told_crime, rumor_crime]}`.
- Из каждой `MemoryEntry` пропозиция строится по таблице `memory_type → pred + роли` (`saw_crime` → `steal`,
  `noticed_missing` → `lose`, `suspects` → `steal` + модальность «думаю»). Новый тип памяти = одна строка таблицы.
- Пропозиции вкладываются: `say(Брана, steal(...))`, `think(я, steal(...))` — так строятся цепочки «Вера говорит, что
  Брана видела…».

### 3.2 Эпистемика (рамка знания)

```
Epistemic { source: seen|heard|rumor|told|inferred, confidence: 0..1,
            chain: [char#7, char#3]   // от кого слышал, ближайший первым; длина = число пересказов
            age: ticks }              // давность
```

Берётся из `MemoryEntry.source/confidence` + новое поле `chain` (сейчас в `remember()` теряется, от кого слух; нужно
сохранять до N=3 звеньев). Рамка выбирает **обёртку** реплики (§5.3): «сама видела», «Брана говорит», «слыхал»,
«болтают», «не знаю, правда ли, но…».

### 3.3 Высказывание (выход сима)

```
Utterance { speaker, listener, act: "inform", tone: "familiar", content: Prop | Topic | none,
            epi: Epistemic, stance: {valence, emphasis, politeness}, intent: "<dialog_plan>", seed }
```

Это то, что сим кладёт в сессию диалога и трассу. Текст из него строится на выводе (`renderUtterance(loc, lang, …)`),
как сейчас `traceText`. Тот же объект уходит агенту (Agent API §4.3 `acts[].content`) — агент пишет свой текст,
но по нашему смыслу, а наш текст получает как подсказку.

## 4. Слой выбора: база правил

### 4.1 Факты контекста

Перед выбором собирается плоский набор фактов (строки и числа): `act=inform`, `tone=rude`, `pred=steal`,
`epi.source=rumor`, `epi.conf=0.49`, `epi.hops=2`, `rel.affinity=0.6`, `rel.familiarity=0.1`, `speaker.trait=gossip`,
`speaker.temperament=choleric`, `speaker.age=old`, `listener.is_victim=1`, `speaker.is_agent=0`, `place=tavern`,
`time=night`, `said.<rule>=3` (сколько раз уже говорил), `topic.age_days=12`…
Набор фактов расширяем: новый «поставщик фактов» в коде = новые оси для всех правил.

### 4.2 Правило

```json
{ "id": "inform.theft.rumor.gossip",
  "when": ["act=inform", "pred.tag=theft", "epi.source=rumor", "speaker.trait=gossip", "epi.conf<0.6"],
  "say": "line.inform.crime.rumor_juicy",        // ключ поверхности (§5)
  "weight": 1.5, "cooldown": "speaker:2d", "once_per": "listener+topic" }
```

- Подходят правила, у которых **все** `when` истинны. Побеждают правила с **наибольшим числом критериев**
  (самое конкретное); среди равных — взвешенный выбор от `agentRng(seed, speaker, tick)`.
- `cooldown`/`once_per` смотрят в память сказанного (`said.*`) — убирает повторы.
- Общие правила-заглушки (`when: ["act=inform"]`) гарантируют, что реплика найдётся всегда.
- Файлы: `content/ai/dialogue_rules/*.json` (сим, без текста), моды добавляют свои файлы. Порядок файлов не важен.
- Матрица тон × отношения превращается в критерии `tone=…`, `rel.affinity>…` — оси не перемножаются, пишутся только
  нужные сочетания.

## 5. Слой поверхности (локализация v0.2)

Совместим с LOC_FORMAT v0.1: старые ключи и плейсхолдеры работают как есть. Добавляется:

### 5.1 Лексемы

Существительные уже есть. Добавляются **глаголы** и **прилагательные** (по языку, в `loc/<lang>/lex_*.json`):

```json
"lex.verb.steal": { "inf": "украсть", "pfv": true,
  "past": { "m": "украл", "f": "украла", "n": "украло", "pl": "украли" },
  "fut":  { "1s": "украду", "2s": "украдёшь", "3s": "украдёт", "1p": "украдём", "2p": "украдёте", "3p": "украдут" },
  "syn":  ["стащить", "утащить", "увести"] },
"lex.verb.steal_x": { "inf": "обчистить", "...": "..." },
"lex.adj.whole": { "m": {"nom":"весь","acc_an":"всего","acc":"весь", "...":"..."}, "f": {...}, "pl": {...} }
```

- В en у глагола `past`, `3s`, `base`, `ing`; у существительного — `sg/pl` и артикль (`a|an|the|∅` выбирается правилом).
- Существительное получает `anim: true` (вин. = род. для одушевлённых м.р. и мн.ч. в ru) и `pl` (мн. число
  со своими падежами).
- Лексемы — данные; генератор (`tools/lexgen.py`) заполняет парадигмы по типам склонения/спряжения, человек правит
  исключения.

### 5.2 Фреймы предикатов (языковые)

Фрейм говорит, как *этот язык* выражает предикат: глагол, управление ролей (падеж, предлог), порядок по умолчанию,
и три формы — **клауза**, **именная группа** (номинализация), **«о чём»**:

```json
"frame.steal": {
  "verb": "steal",
  "roles": { "agent": "nom", "theme": "acc", "source": "у+gen", "loc": "loc_phrase", "time": "time_phrase" },
  "clause":  "{agent} {>time?} {verb:agree=agent} {>source?} {theme}",
  "nominal": "кража {theme:gen} {>source?}",
  "about":   "о краже {theme:gen}"
},
"frame.lose": { "verb": "go_missing", "roles": { "theme": "nom", "source": "у+gen" },
  "clause": "у {source:gen} {verb:agree=theme} {theme}" }
```

Шаблон реплики теперь пишет `{>prop:clause}`, `{>prop:nominal:acc}`, `{>prop:about}` — и строка «Прости за …»,
«Это ты …», «Что знаешь …» склеиваются правильно с любым предикатом. Английский фрейм свой (`"{agent} {verb:past} {theme} from {source}"`),
порядок слов — дело языка, код не знает.

### 5.3 Новые записи в плейсхолдерах

| Запись | Смысл |
|---|---|
| `{>rule}` | раскрыть подправило `rule` (ключ того же языка) с теми же аргументами; у правила может быть несколько вариантов-строк, выбор от сида |
| `{>rule?}` | раскрыть, если все аргументы правила есть, иначе пусто (необязательная роль: «ночью», «у мельника») |
| `{>prop:clause}` / `:nominal` / `:about` | реализовать пропозицию через её фрейм |
| `{verb:agree=agent}` | форма глагола по роду/числу/лицу аргумента и времени пропозиции |
| `{adj.whole:agree=theme:acc}` | прилагательное в роде/числе/падеже существительного |
| `{who:pro}` / `{who:pro:dat}` | местоимение вместо повторного упоминания («он», «ей»), выбирается автоматически при втором упоминании в той же реплике |
| `{x:prep|о}` | предлог с правилом языка (о → об/обо в ru, a → an в en) |
| `{x:ty}` | обращение по регистру: ты/вы, «брат», «господин» — из отношений и статуса |

Валидатор проверяет: каждый фрейм на каждый предикат в базовом языке, у каждой роли есть падеж, раскрытие не
циклится (глубина ≤ 6), все `>rule` существуют.

### 5.4 Обёртки (эпистемика и голос)

Отдельные подправила, которые кладутся вокруг клаузы:

- `wrap.epi.seen` → «Сама видела: {>body}» / «Своими глазами видел{self:g||а}, как {>body}»
- `wrap.epi.told` → «{src} говорит, {>body}» / «Мне {src:nom} рассказал{src:g||а}, что {>body}»
- `wrap.epi.rumor.<полоса>` по уверенности: ≥0.6 «Говорят, {>body}»; 0.4–0.6 «Слыхал, вроде {>body}»;
  <0.4 «Болтают, будто {>body}, но кто их знает»
- `wrap.voice.<черта>`: болтливый добавляет «представь!», «только никому»; осторожный — «не мне судить»; грубый —
  ругательство из словаря. Голос = набор вставок + предпочтения синонимов (`syn`) + длина фразы.
- `wrap.tone.<тон>`: вежливые формулы, обращения.

Каждая обёртка — тоже правило §4 (с критериями), поэтому моды и новые черты просто добавляют свои.

## 6. Шум слухов

### 6.1 Принцип

Искажение — **операция над пропозицией** при пересказе (в `consequences.cpp`, где сейчас `rumorDecay`), детерминированно
от сида. Результат — новая `MemoryEntry` слушателя, со своей (может быть уже ложной) пропозицией. Сим на ней работает:
подозревает, обвиняет, мстит не тому.

### 6.2 Операторы (`content/ai/rumor_noise.json`, всё параметрами)

| Оператор | Что делает | Пример | От чего зависит шанс |
|---|---|---|---|
| `drop_detail` | теряет время/место/количество | «ночью у амбара» → ∅ | число пересказов, давность |
| `vague_theme` | предмет → категория → «что-то» | мука → еда → что-то | уверенность |
| `exaggerate` | количество ↑, предикат → сильнее по шкале (`steal → rob → raid`) | мешок → «весь амбар» | черта «болтун», эмоция |
| `minimize` | обратное, у друзей виновного | «стащил» → «взял немного» | отношение к виновнику |
| `swap_agent` | подмена исполнителя похожим/неприятным | Олег → сын кузнеца | вражда к новому «виновнику», плохая слава, низкая уверенность; **по умолчанию редко** |
| `swap_victim` | путает жертву с соседом | мельник → пекарь | то же |
| `merge` | склеивает два слуха о том же человеке | «и кур таскает, и муку» | наличие второго слуха |
| `invert` | «Олег поймал вора» ↔ «Олег — вор» | | очень редко, низкая уверенность |
| `attribute_shift` | теряет/путает источник в цепочке | «Брана видела» → «кто-то видел» | число звеньев |

- Шкалы для `exaggerate/minimize` — в `predicates.json` (`scale: ["take", "steal", "rob", "raid"]`), для количеств —
  в `rumor_noise.json`.
- Уверенность падает как сейчас (`rumorDecay`), плюс каждое сработавшее искажение может давать штраф/бонус
  (болтун преувеличивает, но *увереннее*).
- Слушатель может **сверить**: если у него есть своя память об этом (видел сам), искажение отбрасывается, а к
  рассказчику падает доверие («врёт»). Это даёт естественную «проверку слухов» без сценариев.
- Флаг `truth` у пропозиции: исходный факт хранится в событии мира (для отладки/QA, отчёт «насколько слух
  расползся от правды»), персонаж его не видит.

### 6.4 Реестр правды (решение пользователя 21.11)

Источник истины хранится **всегда, в ядре сима**, а не в памяти персонажей, чтобы можно было доказать, обелить себя
или другого, выиграть суд, разоблачить клеветника.

- `World::facts` — реестр фактов: `Fact {id, tick, pred, roles (истинные), place, witnesses[], evidence[], tags}`.
  Создаётся в момент события (`afterDeed`, драка, подарок, смерть…) — до того, как кто-то что-то запомнил.
  Сохраняется в сейв и реплей, не теряется после `trailDays` и после смерти участников. Персонажи сами в реестр не
  смотрят.
- Каждая `MemoryEntry` и каждая искажённая пропозиция несут `fact_id` + `chain` (от кого слышал). Поэтому любой слух
  можно сверить с правдой и пройти цепочку до того, кто исказил или соврал.
- **Улики** (`evidence[]`): кто был свидетелем (`seen`), где лежит вещь (украденный мешок в чужом доме), следы,
  признание. Улика — ссылка на объект/персонажа, мир сам её «помнит»; найти её в игре можно действиями
  (обыскать, спросить свидетеля, показать вещь).
- **Доказать/обелить**: акт `prove`/`vouch` = `inform` с пропозицией + ссылкой на улику или свидетеля. Слушатель
  проверяет: свидетель подтверждает (его память с тем же `fact_id` и `source=seen`), вещь найдена — уверенность в
  ложной версии падает, доверие к тому, кто её распустил, падает, к обвинённому — растёт, репутация восстанавливается.
  Суд (тред AL-37) опирается на тот же реестр: приговор по уликам и показаниям, а не по слухам.
- Ложь (`lie`) создаёт пропозицию **без** факта (или с противоречием факту) — разоблачима тем же механизмом.
- QA/отладка: отчёт «правда vs слух» по каждому факту.

### 6.3 Поверхностный шум (только текст)

Не меняет смысл: оговорки («ну, этот… Олег»), повтор, перебивка, «эээ», обрыв — правила с критериями
`speaker.state=drunk|scared|tired`, `epi.conf<…`. Отдельно от смыслового шума, чтобы QA мог выключать.

## 7. Не только слухи

Та же цепочка покрывает все реплики:

- Речевые акты `dialogue.json` (greet, ask, request, accuse, promise, threaten…) — правило + шаблон с `{>prop:*}`.
  Существующие 268 строк переносятся как заглушки-правила с теми же условиями `pre` (ничего не теряется).
- Память (`memory.*.text`), хроника, трасса, «бабблы» над головой (ambient barks: «Опять дождь», «Хлеба бы»), реакции
  на события, торг, обвинение на суде, молитва, песни/истории у костра (`tell_story` — пропозиции из истории мира).
- Меню игрока без агента: подписи пунктов строятся тем же реализатором в форме `:about` («Рассказать о краже муки»).

## 8. Расширяемость и моды

- Новый предикат: запись в `predicates.json` + фрейм в каждом языке (валидатор скажет, где нет).
- Новый язык: каталог `loc/<lang>/` + `_grammar.json` (падежи, правило числа, предлоги) + лексемы + фреймы; код не
  меняется. Языки без падежей просто не используют `:case`.
- Новая черта/голос: правила `wrap.voice.<черта>` + синонимы.
- Мод: свои файлы правил/лексем/фреймов, побеждают по специфичности, не по порядку загрузки.

## 9. Инструменты и проверки

- `altera_sim_runner --say <seed> --act inform --pred steal ...` и `--dialogue-corpus N` — выгрузка N реплик в
  файл для чтения глазами (корпус по каждому акту × тону × уверенности).
- Тесты: согласование (род/падеж/число на таблице имён и предметов), отсутствие `[ключ]` и `{слот}` в корпусе,
  доля повторов, детерминизм от сида, ru и en.
- Отчёт «расползание слуха»: по миру за N лет — сколько слухов ложные, средняя длина цепочки, сколько ложных
  обвинений.

## 11. Решения пользователя (21.11)

1. Подмена виновника (`swap_agent`) — **включена по умолчанию**, редко, при низкой уверенности; правда остаётся в
   реестре §6.4, поэтому ложное обвинение можно опровергнуть.
2. Регистр **ты/вы**: «ты» по умолчанию, «вы/господин» к знати и старшим, по статусу и отношениям.
3. **Просторечие/архаика** умеренно по умолчанию, сильнее у деревенских и стариков (голос §5.4).
4. Языки: **ru базовый + en**, третий язык в планах — фреймы проверяются на независимость от двух языков.
5. Модель AL-31 (PR 15) берётся как есть; `chain`, `fact_id` и вызов шума добавляются своими PR.
6. **Источник истины всегда в ядре** (§6.4).
