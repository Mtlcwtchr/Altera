# Data-driven контент (LR-142)

Цель: на уже собранной игре класть JSON в папку данных, и всё подтягивается без пересборки.
Пересборка нужна только для принципиально новой механики, которую нельзя выразить связями в данных.
Данные связываются по id; строки только там, где это текст (и текст идёт ключами локализации).

Код: `src/sim/data_fs.{hpp,cpp}` (слои), `src/sim/expr.{hpp,cpp}` (язык выражений),
`src/sim/formulas.{hpp,cpp}` (именованные формулы), `src/sim/char_expr.{hpp,cpp}` (контекст персонажа),
`src/sim/templates.{hpp,cpp}` (шаблоны). Тесты: `tests/test_lr_sim_data.cpp`.

## 1. Где игра ищет данные

Корень `content/` выбирается при старте (`data::mountDefault`), первый найденный:

1. `LR_DATA` (переменная окружения): папка `content/` или папка, где лежит `content/`;
2. `<папка exe>/data/content` — так раскладывается сборка для игры;
3. `<папка exe>/content`;
4. `content/` в одном из 4 родителей exe — сборка внутри репозитория (`cmake-build-*`);
5. исходники (путь, вшитый при сборке).

`--root <папка>` у `lr_game_2d` по-прежнему указывает дерево напрямую. В консоли при старте печатается,
какой корень и какие моды подключены.

## 2. Слои и моды

Мод — папка, повторяющая раскладку `content/`: `mods/<имя>/ai/items.json` ложится поверх
`content/ai/items.json`, `mods/<имя>/species/naga.json` добавляет новый народ.

Где ищутся моды: `<корень>/../mods/*` и `<папка exe>/mods/*`, плюс `LR_MODS` (пути через `;`).
Порядок: `mods/load_order.json` (`{"mods": ["a", "b"], "off": ["c"]}`), остальные по имени.
Папки на `_` и `.` пропускаются (`_disabled`).

Правила наложения файла:

- по умолчанию файл слоя **заменяет** файл ниже;
- если в корне JSON стоит `"_merge": true`, он **вливается**: объекты по ключам вглубь, массивы
  объектов с `id` по id (тот же id сливается, новый дописывается, `{"id": "x", "_remove": true}`
  удаляет), остальное заменяется;
- папки (виды, культуры, правила диалогов, локализация, формулы, шаблоны) — объединение файлов всех слоёв.

Пример мода, добавляющего предмет и меняющего питательность хлеба:

```json
{ "_merge": true,
  "items": [ {"id": "honey_cake", "tags": ["food", "treat"], "nutrition": 0.4, "value": 3},
             {"id": "bread", "nutrition": 0.55} ] }
```

## 3. Горячая перезагрузка

`lr_game_2d` раз в секунду сверяет все прочитанные файлы и папки всех слоёв (правка, новый или удалённый
файл), а также папки модов: мод, положенный во время игры, подключается без перезапуска. При изменении: заново грузится весь контент сима, локализация, JSON клиента (`sprites_2d`, `ui`),
окно перечитывает спрайты, карту и HUD и перерисовывает всё. Мир продолжает идти с новыми данными
(id сохраняются, числа и правила меняются). Если новые данные не грузятся (ошибка JSON, неизвестный id),
в консоль пишется причина и остаются старые данные. Выключить: `--no-hot-reload` или `LR_HOT_RELOAD=0`.

Модули сима кэшируют правила по `data::cacheKey(dir)`, где есть поколение данных, поэтому после
перезагрузки читают свежее. Новый читатель контента: `data::readJson(path)` / `data::InFile`
вместо `std::ifstream`, `data::listFiles(dir)` вместо обхода папки.

## 4. Формулы

Язык — бывший craft-expr (`doc/design/CRAFT_EXPR.md`), теперь общий: `+ - * /`, сравнения, `and or not`,
`?:`, `min max clamp abs floor ceil round pow sqrt exp log lerp sign step`, для шансов `noise(mean, sd)`
(нормальная выборка) и `p_over(mean, sd, t)` (вероятность, что выборка выше t — для статистического LOD).
Модули добавляют функции `registerExprFn` и префиксы имён `registerExprPrefix`.

Именованные формулы — `content/ai/formulas/*.json` (любое число файлов, моды добавляют свои):

```json
{ "constants": {"persuade_cap": 0.95},
  "formulas": [
    {"id": "mood_edge", "expr": "need.fun * 0.2"},
    {"id": "persuade", "params": ["skill"], "defaults": {"skill": "eloquence"},
     "expr": "min(cfg.persuade_cap, attr.charisma * 0.6 + skill.$skill * 0.4 + f.mood_edge)",
     "min": 0, "max": 1, "doc": "…"},
    {"id": "charm_mix", "expr": {"attr.charisma": 0.5, "skill.eloquence": 0.3}}
  ] }
```

- имена: `attr.<id>`, `skill.<id>`, `trait.<id>` (1/0), `need.<id>`, `rep.<ось>`, `rel.<ось>` (к другой
  стороне), `age`, `t.<любое из этого>` (другая сторона), `arg.<имя>` (число, которое передаёт код),
  `cfg.<константа>`, `f.<формула>` / `f.<формула>(арг, ключ=арг)`;
- `$param` подставляется текстом, в том числе внутри имён (`skill.$skill`); внутри имени аргумент
  обязан быть id;
- `expr` объектом — взвешенное среднее;
- `min`/`max` обрезают результат;
- ошибки загрузки (контент не грузится, `validate_content.py formulas` их тоже ловит): неизвестная
  формула, неизвестный id (`trait.xxx`, `skill.xxx`…), имя без известного префикса, нет константы,
  несвязанный параметр, синтаксис, цикл.

Код спрашивает формулу по id: `content.formulas.eval("persuade", ctx)` с `CharExprCtx` персонажа, или
`content.formulas.evalArgs("realm_levy", {{"militia", m}, ...}, старое_правило)` — старое правило в коде
остаётся запасным, пока формулы нет. Первый перенос: сила владения в войне, `content/ai/formulas/realm.json`.

## 5. Шаблоны

Для любых списков записей с `id` (сейчас в `Content::load`: items, objects, interactions, traits,
needs, moodlets, knowledge; другие модули зовут `expandTemplates` сами):

```json
{"id": "sword_iron", "extends": "blade", "use": ["mix.sharp"], "args": {"metal": "iron"}, "+tags": ["weapon"]}
```

- `extends` — один родитель (из книги `content/ai/templates/*.json` или из того же списка);
- `use` — примеси по порядку, затем сама запись; объекты вглубь, массивы заменяются, `+ключ` дописывает;
- `params`/`defaults` у шаблона, `args` у записи, `$name` в строках; строка ровно `"$name"` берёт
  значение аргумента как есть (число, объект);
- `"abstract": true` — только шаблон, в контент не попадает;
- неизвестный id, цикл, несвязанный параметр — ошибка загрузки.

## 6. Проверка

`python tools/validate_content.py` (подкоманды `formulas`, `templates`, `mods`, `--mods <папка>`);
авторитетна загрузка в C++ (`Content::load` бросает со списком ошибок; тест `lr_data_mod_over_real_content`).
