# Altera — формат локализации (`content/loc/`), v0.1

Локализация с первого дня: в данных (`content/ai/*.json`) и в коде (`src/sim/`) — только **ключи** и параметры. Тексты
лежат в `content/loc/<lang>/*.json` и собираются при выводе (трасса, отчёты, диалоги, UI). Код: `src/sim/loc.hpp`
(`Loc`, `formatLoc`, `validateLoc`, `traceText`, `localizeReport`).

## 1. Файлы и языки

```
content/loc/
  loc.json            { "base": "ru", "fallback": "ru", "languages": ["ru", "en"] }
  ru/names.json       имена id контента (предметы, объекты, нужды, черты, цели, задачи, взаимодействия, ...)
  ru/social.json      речевые акты, оси отношений и репутации, пары статусов, роли в доме, обязательства, причины смерти
  ru/dialogue.json    реплики диалогов: dialogue.<template>.<variant>
  ru/trace.json       trace.<code>, reason.<code>, report.idle.<code>, chronicle.<code>
  en/...              те же ключи
```

- **base** — базовый язык: в нём обязан быть каждый ключ, на который ссылаются данные или код (иначе ошибка валидатора).
- **fallback** — откуда берётся текст, если перевода нет. Цепочка поиска: запрошенный язык → `fallback` → `base`.
  Ключ, которого нет нигде, выводится как `[ключ]` (видно в трассе, но не роняет игру).
- **languages** — каталоги языков. Файлов в каталоге сколько угодно, имена файлов произвольные (`*.json`), читаются в
  алфавитном порядке. Один и тот же ключ в двух файлах одного языка — предупреждение, побеждает первый.
- Вложенные объекты разворачиваются в ключи через точку: `{"trace": {"goal": {"done": "..."}}}` → `trace.goal.done`.
  Поле `"_doc"` на любом уровне игнорируется.

## 2. Значения

Значение ключа — либо **строка-шаблон**, либо **существительное** (объект с полем `nom`):

```json
"hearth": { "name": { "nom": "очаг", "gen": "очага", "dat": "очагу", "acc": "очаг", "ins": "очагом", "pre": "очаге", "g": "m" } }
```

- Падежи: `nom` `gen` `dat` `acc` `ins` `pre` (именительный … предложный). Обязателен только `nom`; отсутствующая форма
  при выводе заменяется на `nom`.
- Род `g`: `m`, `f`, `n`, `pl` (мн. число как «род» для согласования). Используется выбором по роду `{x:g|...}`.
- Существительное, выведенное как обычный текст (`Loc::text`), даёт `nom`.
- В языках без падежей (en) существительные пишутся просто строками.

## 3. Плейсхолдеры

| Запись | Смысл |
|---|---|
| `{speaker}` | значение аргумента: строка как есть, число (целое без дробной части, иначе до 2 знаков; в `ru` — с запятой), существительное — `nom`, массив — через запятую |
| `{listener:dat}` | падежная форма аргумента-существительного (`nom gen dat acc ins pre`); нет формы — `nom` |
| `{speaker:g\|рад\|рада}` | выбор по роду аргумента: формы в порядке `m\|f[\|n\|pl]` (2–4 формы); род берётся из `g`, при отсутствии `n`/`pl`-формы или рода — первая форма |
| `{qty:plural\|ягода\|ягоды\|ягод}` | множественное число по числовому аргументу: `ru` — 3 формы `one\|few\|many`, `en` — 2 формы `one\|other` |
| `{{`, `}}` | литеральные фигурные скобки |

Плейсхолдер выводит **только слово**; число пишется отдельно: `{qty} {qty:plural|ягода|ягоды|ягод}`.

Пустая форма допустима: `рад{speaker:g||а}` → «рад» / «рада».

Правила множественного числа (`pluralCategory`):
- `ru`: `n % 10 == 1 && n % 100 != 11` → one; `n % 10 ∈ 2..4 && n % 100 ∉ 12..14` → few; иначе many; дробное → few
  («1,5 ягоды»).
- `en` (и любой другой язык по умолчанию): `n == 1` → one, иначе other.
- Правило выбирается по языку, **из которого взят шаблон** (если сработал fallback на `ru`, считается по-русски).

Имя аргумента: латиница, цифры, `_`. Аргумент, которого нет, — ошибка форматирования; в тексте остаётся `{имя}`.

## 4. Ключи

| Ключ | Откуда требуется |
|---|---|
| `item.<id>.name`, `object.<id>.name`, `need.<id>.name`, `moodlet.<id>.name`, `fsm.<state>.name` | id из `items/objects/needs/fsm.json` |
| `trait.<id>.name`, `trait.<id>.desc` | `traits.json` |
| `goal.<id>.name` (+ `goal.queued.name`, `goal.player_action.name` — цели уровня кода) | `goals.json` |
| `task.<id>.name` | `htn.json` |
| `interaction.<id>.name`, `risk.<id>.name` | `interactions.json` (`risk[].id`) |
| `speech.<act>.name` | `dialogue.json/speech_acts` и `interactions[].speech` |
| `dialogue.<template>.<variant>` | `dialogue.json/templates[].variants` |
| `rel.<axis>.name` | оси отношений (код) |
| `reputation.<axis>.name`, `status_pair.<id>.name`, `household_role.<id>.name`, `cause.<id>.name`, `commitment.<id>.name` | `config.json` |
| `trace.<code>` | коды трассы (`traceCodes()` в `loc.cpp`; тест проверяет, что всё испускаемое там есть) |
| `reason.<code>` | коды причин (`reasonCodes()`): голова причины до первого `:` |
| `report.idle.<code>` | причины простоя отчёта (`idleCodes()`) |
| `chronicle.<code>` | записи хроники (`chronicle.death`) |

## 5. Сборка текста трассы, причин и отчётов

Трасса и отчёт хранят **код и параметры** (`TraceEntry{code, params}`, `ChronicleEntry{code, params}`). Текст
собирается на выводе: `traceText(loc, lang, world, character, entry)` = `loc.text(lang, "trace." + code, args)`.

Аргументы (`locArgs`) строятся из параметров; параметры известных видов превращаются в имена/существительные:

| Параметр | Становится |
|---|---|
| `goal`, `was`, `chosen` | `goal.<v>.name` (`queued:<task>` → `task.<task>.name` или `interaction.<task>.name`) |
| `task` | `task.<v>.name`, иначе `interaction.<v>.name` |
| `action`, `interaction` | `interaction.<v>.name` |
| `state`, `root` | `fsm.<v>.name` |
| `need`, `item`, `cause` | `need.<v>.name`, `item.<v>.name`, `cause.<v>.name` |
| `to`, `object`, `target_type` | `object.<v>.name` |
| `why`, `for` (строка) | текст причины (`reasonText`) |
| `who`, `speaker`, `listener`, `actor`, `target` (id) | персонаж: `{"nom": имя, "g": "m"/"f"}`; id объекта → `object.<type>.name` |
| `self` (добавляется всегда) | персонаж, чья это трасса |

Остальные параметры передаются как есть. Ссылка на отсутствующий ключ даёт сам id (не `[ключ]`).

**Причины** (`reasonText`): `голова:остаток` → `reason.<голова>` с аргументом `{detail}`. Остаток с `:` разбирается
рекурсивно (`fsm.lost:pre:has:meal>=1` → «действие сорвалось: не выполнено условие has:meal>=1»); простой остаток,
совпадающий с id объекта/предмета/цели/взаимодействия/нужды/задачи, заменяется его именем. Неизвестная голова — причина
выводится как есть.

**Отчёт** (`localizeReport`): добавляет `text` в `summary.why_idle[]`, `summary.plan_failures[]`, `summary.deaths[]` и
`why_text` в `summary.why_hunger[]`; поле `lang`.

**Раннер**: `altera_sim_runner --lang ru|en [--loc DIR]` — тексты в трассе (`--trace`, поле `text`) и отчёте
(`--report`). `--validate` проверяет и контент, и локализацию; ошибки loc — код выхода 1.

## 6. Валидатор (`validateLoc`)

Ошибки:
- в базовом языке нет обязательного ключа (§4);
- синтаксис шаблона: незакрытая/лишняя скобка, вложенные `{`, пустое или недопустимое имя, неизвестный модификатор,
  падеж с формами, `g` не с 2–4 формами, `plural` не с 3 формами (`ru`) / 2 (`en`);
- существительное: неизвестная форма (не падеж и не `g`), форма не строка, род не из `m f n pl`;
- нет таблицы базового или fallback-языка.

Предупреждения:
- нет перевода обязательного ключа в небазовом языке (сработает fallback);
- ключ есть в переводе, но нет в базовом языке (сирота);
- в переводе есть плейсхолдер, которого нет в базовом шаблоне;
- дубликаты ключей между файлами, не-строковые значения.

## 7. Ограничения v0.1

- Имена персонажей генерируются и пока не склоняются (у аргумента-персонажа есть только `nom` и род). Генератор имён
  сможет отдавать падежные формы тем же объектом.
- Диалоговые реплики получают `speaker`/`listener` и параметры шаблона от слоя диалогов (шаг 4); их набор валидатор не
  проверяет, кроме синтаксиса.
- Числа форматируются без разрядных разделителей.
